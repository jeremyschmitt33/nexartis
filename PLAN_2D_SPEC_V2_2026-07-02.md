# Module Plan 2D — SPEC V2 ARBITRÉE
**02/07/2026 — Équipe : 3 experts (Design/UX, Métiers, Scan IA/3D) + Confrontateur + arbitrage Claude. Maquette `mockup_plan_2d_editeur_v2.html` à valider par Jerem. RIEN N'EST CODÉ DANS L'APP.**

## 0. Principe d'arbitrage

La MAQUETTE montre toute la vision (scan, 3D, multi-lots) pour que Jerem juge sur pièces. Le DÉVELOPPEMENT, lui, est phasé — le Confrontateur a raison : tout livrer d'un coup avec notre historique de régressions garantirait qu'aucune brique ne tienne. Les badges de phase figurent dans la maquette.

**Test de vérité retenu (Confrontateur)** : un artisan doit obtenir UN devis correct pour UNE pièce réelle de SON métier en moins de 10 minutes, sinon il classe l'outil « gadget » et n'y revient jamais. Toute décision est jugée là-dessus.

## 1. Profils métier (architecture validée à l'unanimité)

**Le moteur calcule TOUT en permanence ; le profil métier ne fait que filtrer l'affichage.** Profils = config TypeScript versionnée (pas de DB). Le plan JSONB reste agnostique du métier.

- Défaut = métier du compte. Sélecteur « Vue métier » dans l'en-tête du panneau métrés, mémorisé par plan, « Tous les métrés » toujours en 1re position. La palette de symboles suit la vue (les autres outils restent accessibles via « Plus d'outils », jamais supprimés).
- **Dev phase 1 : 6 profils** — peintre, carreleur/solier, plaquiste, électricien, plombier + multi-services/TCE. Maçon, menuisier, chauffagiste : codés mais flag off tant que non validés par un artisan du métier réel (un métré non validé terrain = un passif, pas un actif). Serrurier/vitrier : exclus, assumé (usage plan quasi nul ; leur différenciateur est ailleurs, cf. COP serrurier). Couvreur/façadier/cuisiniste/paysagiste : V3 (élévations/pentes/plan masse).
- NF C 15-100 : toujours « suggestion indicative — à vérifier », JAMAIS « conforme » (la conformité = le Consuel).
- Urbanisme : PAS d'« assistant DP/permis ». Une ligne d'info neutre : « Emprise créée : 14,7 m² — renseignez-vous en mairie » + lien service-public.fr. Aucun verdict.

## 2. Éditeur — corrections V1 et UX V2

- **Formes : Rectangle, en L, et POLYGONE LIBRE dès la V2** (points cliqués). Exigé par le vieux bâti (60 % du parc : murs pas droits, trapèzes) — trou majeur détecté par le Confrontateur.
- **Ajout pièce : grille de CHIPS** (fini la datalist) : 8 fréquentes visibles (Salon, Cuisine, Chambre, SdB, WC, Entrée, Couloir, Garage) + « Voir tout ▾ » (22 types : Séjour, Salle d'eau, Dégagement, Bureau, Buanderie, Cellier, Dressing, Cave, Combles, Mezzanine, Véranda, Terrasse, Balcon, Local technique) + champ libre. Auto-suffixe « Chambre 2 ». Enchaînement « + Ajouter une autre pièce ».
- **FAB « + Ajouter une pièce »** bas-centre du canvas (l'action n°1 n'est plus cachée). État vide : 3 boutons (Ajouter une pièce / Photo d'un plan / Voir comment ça marche).
- **Indicateur de sauvegarde** topbar 3 états (Enregistré / Enregistrement… / Hors ligne). Offline V2 = honnête et minimal : bannière + copie locale de secours ; l'édition offline complète est un projet en soi (reporté).
- Création de plan en 2 étapes : métier (grille de cartes, pré-sélectionné) → méthode (De zéro / Photo d'un plan [badge Complet] / Dupliquer un plan). Duplication de plans entre chantiers = rétention (le plombier qui fait 10 SdB).
- Actions sur sélection dans le panneau droit (renommer, calque, dupliquer, supprimer) — PAS de toolbar flottante type Figma (un pattern de moins = des bugs de moins). Suppression = toast « Annuler » 8 s, pas de modal.
- Onboarding Driver.js 4 bulles max (FAB → palette → calques → CTA devis). Cibles tactiles 44 px, clavier numérique, 2 doigts pan/zoom.
- Escaliers/trémies/sous-pentes (raté par tous, relevé par le Confrontateur) : V2 = champ « déduction de surface » par pièce (m² soustraits, libellé libre « trémie escalier ») ; HSP rampants = V3.

## 3. Injection devis — LE différenciateur, tout le soin ici

- Tiroir avec cases à cocher (tout coché), groupement par LOT (sections de devis existantes), quantités mono, mention des règles de déduction appliquées, bandeau orange pour les métrés du calque Projet.
- Anti-doublon : « 3 lignes déjà envoyées — remplacer ou ajouter ? ». Écran de succès : « 8 lignes ajoutées au devis DEV-2026-042 → Ouvrir le devis / Rester sur le plan ».
- Lien vivant `source:{planId, revisionId, roomId, metric}` : plan modifié → badge « métré modifié, recalculer ? » sur les lignes (jamais de recalcul silencieux). **Règle nouvelle : ligne éditée à la main dans le devis = DÉLIÉE (badge « lien rompu »), jamais d'écrasement** — l'artisan retouche toujours ses prix.
- Ventilation multi-lots automatique de la véranda (6 lots) : DÉMO dans la maquette, mais en dev = V2.1+ (dépend de formules maçon/couvreur/chauffagiste non validées). V2 dev = injection multi-sections simple.

## 4. Import photo d'un plan (« scan ») — V2, porte discrète, offre Complet

- Réalité mesurée (Blueprint-Bench) : les LLM vision sont mauvais en géométrie estimée, très bons en lecture de cotes ÉCRITES. Donc : **l'IA lit la topologie + les cotes écrites ; la géométrie finale est RECONSTRUITE à partir des cotes validées une à une par l'artisan.** Le polygone IA ne sert qu'à pré-positionner.
- Pipeline : photo → R2 → Gemini Flash (responseSchema strict, temperature 0, `valeur_texte` + `valeur_mm` + confiance par cote) → validation Zod serveur (cohérence surface/cotes ±8 %, bornes de vraisemblance) → **écran de validation pièce par pièce OBLIGATOIRE** (badges vert « lu sur le plan » / or « à vérifier » / rouge « non lisible »), gate serveur : aucun métré injectable tant que tout n'est pas validé. Horodatage de validation conservé (litiges).
- Positionnement honnête (Confrontateur) : le cas nominal (plan propre et coté) est minoritaire → porte discrète, attentes cadrées (« plan coté et lisible uniquement »), messages d'échec assumés (croquis sans cotes, cadastral, flou), fallback saisie manuelle toujours à un clic. Coût ~0,004 $/scan, rate-limit 10/h.
- Disclaimers : « L'import lit les dimensions écrites sur votre plan. Il ne mesure pas le dessin. » / « Ne remplace pas un relevé sur place. » RGPD : dire que la photo transite par l'API Google ; plan du domicile = donnée personnelle (suppression client = suppression plan ; à ajouter à la politique de confidentialité).

## 5. Vue 3D — extrusion isométrique maison, V2.1

- Projection iso 30° du plan (sx=(x−y)·cos30, sy=(x+y)·sin30−z), murs extrudés à la HSP, painter's algorithm, ouvertures, **toggle Avant/Après du calque projet** (l'argument de closing), rotation 90°, capture PNG. Zéro coût, exact par construction, ~600 lignes.
- Verdict Confrontateur accepté : zéro métré, zéro euro direct → **V2.1**, après stabilisation du socle. Présent dans la maquette (badge V2.1) pour validation du concept.
- Image concept IA (photo façade → véranda, ~0,04 €/img) : V3, option Complet, filigrane « Illustration non contractuelle générée par IA », jamais insérée automatiquement au devis. Three.js : rejeté.

## 6. Gating (aligné stratégie prix)

Éditeur 2D + métrés + injection = **toutes offres** (l'avantage concurrentiel frontal, la concurrence surtaxe). Scan photo, ventilation multi-lots, 3D, image IA = **Complet 25 €**. Jamais de module surtaxé séparé (leçon avis magicplan).

## 6 bis. Réserves du Vérificateur sur la maquette (audit du 03/07/2026)

- **INTERDIT EN DEV** : l'heuristique « ÷2 » des ouvertures mitoyennes utilisée dans la maquette (une porte entre 2 pièces est déclarée 2 fois, le comptage menuiserie/maçonnerie divise par 2). Artifice de démo qui produit un métré faux dès que l'artisan saisit lui-même. En dev : vraie notion d'ouverture partagée (une ouverture = un objet, référencé par 2 pièces).
- Indicateur « Hors ligne » + bannière : non démontrés dans la maquette, exigés en dev (§2).
- Le badge « métré modifié, recalculer ? » (lien vivant §3) n'est pas démontré dans la maquette : exigence dev inchangée.
- Métrés recalculés à la main par le Vérificateur : écart ZÉRO sur les 6 pièces × 3 modes de déduction, plinthes, véranda 14,70 m², NF C 15-100. Le mot « conforme » n'apparaît nulle part à l'écran.

## 7. Risques existentiels (à relire avant chaque push)

1. **Un métré faux dans un devis signé** → peu de métiers, validés terrain, disclaimers, montants toujours éditables.
2. **Contamination du cœur devis** → code isolé, injection append-only, jamais de modification silencieuse du devis.
3. **Coût d'opportunité vs e-facture sept. 2026** → phasage strict, le socle d'abord.
